# 架构决策记录

本目录用于记录对系统边界、数据所有权、集成方式、安全边界、组件组织或长期演进具有持续影响的架构和关键技术决策。

ADR 只回答“选择了什么方案、为什么这样选择、付出了什么代价”。它不替代其他事实源：

- 产品目标、业务范围和产品进度由本项目 `docs/requirements/` 中的 PRD 维护；
- 单次研发变更的行为、验收、设计和任务由 OpenSpec 维护；
- 跨系统字段、状态和错误语义以已确认的共享契约为准；
- 实际实现状态由代码、测试和 Git 历史体现。

## 适用场景

以下情况通常需要 ADR：

- 改变 `holdlens-server` 的领域、事实源、持久化、权限、审计或跨项目边界；
- 选择会长期约束后续实现的集成模式、模块边界或基础设施方案；
- 对安全、隐私、事务、兼容或数据迁移方式作出难以轻易撤销的取舍；
- 推翻或部分取代已有 ADR。

普通功能需求、接口字段调整、状态枚举、重试参数、局部重构和实施步骤通常不单独创建 ADR，应进入本项目 PRD、已确认契约或 OpenSpec 的对应位置。

## 状态与替代关系

ADR 状态使用：

- `提议`：仍在评审，尚未成为约束；
- `已采纳`：当前有效；
- `已取代`：已被后续 ADR 完全替代；
- `已废弃`：不再采用且没有替代决策。

已采纳 ADR 原则上保留历史决策原文，只补充勘误、状态和替代关系。决策发生实质变化时，应创建新 ADR，并在新旧 ADR 中明确完全或部分取代关系。

ADR 不负责维护 PRD 与 OpenSpec Change 的映射。相关 OpenSpec 可以引用 ADR；ADR 只在理解决策所必需时引用其他资料。

## 文件与模板

文件名使用连续编号和小写连字符主题，例如：

- `adr-001-server-domain-boundaries.md`
- `adr-002-agent-async-fund-refresh.md`

创建 ADR 时优先从 [adr-template.md](adr-template.md) 复制。模板可以按复杂度删减，但应保留决策信息、背景、决策、取舍原因和影响。
