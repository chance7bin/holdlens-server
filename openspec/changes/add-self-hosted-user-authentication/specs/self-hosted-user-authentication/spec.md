## ADDED Requirements

### Requirement: 注册独立本地账号

系统 SHALL 允许匿名调用方使用合法用户名和密码创建独立账号，并 SHALL 保证新账号不继承固定用户 1 的任何业务数据。

#### Scenario: 注册有效新账号

- **当** 调用方提交未占用的合法用户名和满足长度要求的密码
- **那么** 系统创建 ACTIVE 账号并返回账号 ID 与规范化用户名
- **并且** 账号 ID 不等于 1，资产、记账、自选和持仓初始查询均为空

#### Scenario: 并发注册相同用户名

- **当** 两个请求并发注册规范化后相同的用户名
- **那么** 系统只创建一个账号
- **并且** 另一个请求得到稳定的用户名已占用错误

#### Scenario: 注册参数不合法

- **当** 用户名或密码不满足服务端规则
- **那么** 系统拒绝注册且不写入账号或会话

#### Scenario: 凭据安全保存

- **当** 注册成功
- **那么** 数据库只保存 BCrypt 密码哈希
- **并且** 明文密码不出现在数据库、日志或响应中

### Requirement: 使用账号密码创建可撤销会话

系统 SHALL 校验本地账号凭据，并 SHALL 在成功后签发具有有效期的高熵不透明 Bearer token。

#### Scenario: 登录成功

- **当** ACTIVE 且未锁定账号提交正确密码
- **那么** 系统返回原始 Bearer token、到期时间和账号摘要
- **并且** 数据库只保存 token 的 SHA-256 摘要

#### Scenario: 用户名不存在或密码错误

- **当** 调用方提交不存在的用户名或错误密码
- **那么** 系统返回相同的登录失败状态和消息
- **并且** 响应不泄露用户名是否存在

#### Scenario: 连续登录失败触发锁定

- **当** 同一账号连续失败达到配置阈值
- **那么** 系统在配置时长内拒绝后续登录
- **并且** 锁定响应与普通凭据错误保持相同对外语义

#### Scenario: 登录成功重置失败状态

- **当** 未锁定账号使用正确密码登录
- **那么** 系统清零失败次数和锁定时间并创建会话

### Requirement: 受保护 API 使用可信身份

系统 SHALL 在进入用户业务 Controller 前认证受保护的 `/api/**` 请求，并 SHALL 只把认证上下文中的账号 ID 作为业务用户 ID。

#### Scenario: 有效会话访问私有数据

- **当** 请求携带有效、未过期且未撤销的 Bearer token
- **那么** 系统以该会话所属账号 ID 执行业务查询或写入
- **并且** 不使用调用方参数决定数据所有者

#### Scenario: 缺失或无效会话

- **当** session 模式下受保护请求缺失 token，或 token 无效、过期、已撤销
- **那么** 系统返回 HTTP 401
- **并且** 不进入目标 Controller 或执行业务读写

#### Scenario: 请求 userId 与可信身份不一致

- **当** 受保护请求显式携带的过渡 `userId` 与认证账号 ID 不同
- **那么** 系统返回 HTTP 403
- **并且** 不泄露目标用户是否存在或拥有相关记录

#### Scenario: 未显式配置的新 API

- **当** Server 在 `/api/**` 下增加非注册、非登录接口
- **那么** 该接口默认要求认证
- **并且** 不因遗漏白名单而匿名开放

### Requirement: 查询并退出当前会话

系统 SHALL 允许已认证用户查询自己的账号摘要，并 SHALL 允许其撤销当前会话。

#### Scenario: 查询当前账号

- **当** 已认证用户调用当前账号接口
- **那么** 系统只返回当前账号 ID 和用户名
- **并且** 不返回密码哈希、失败次数、锁定状态或其他会话令牌

#### Scenario: 退出当前会话

- **当** 已认证用户调用退出接口
- **那么** 系统撤销当前会话
- **并且** 相同 token 后续访问受保护 API 返回 HTTP 401

#### Scenario: 重复使用已撤销令牌

- **当** 客户端再次携带已经撤销的 token 请求退出或其他受保护接口
- **那么** 系统返回 HTTP 401
- **并且** 会话保持已撤销且不恢复有效性

### Requirement: 开发模式保持本地调试能力

系统 SHALL 提供受限的固定用户认证模式，使本地开发无需先登录，同时 SHALL 防止该模式用于非开发环境。

#### Scenario: dev 使用固定用户模式

- **当** dev 环境以 fixed 模式启动
- **那么** 受保护请求无需 Bearer token 即以配置的固定用户 1 执行
- **并且** 现有本地用户 1 数据仍可调试

#### Scenario: dev 切换真实会话模式

- **当** 开发者在 dev 环境显式选择 session 模式
- **那么** 注册、登录、认证、退出和新账号空数据链路与非开发环境一致

#### Scenario: 非开发环境误用固定模式

- **当** 非 dev/test profile 配置 fixed 模式
- **那么** 应用启动失败并给出不包含敏感配置的明确错误

### Requirement: 用户认证不替代内部服务认证

系统 SHALL 将用户认证边界限制在 `/api/**`，并 SHALL NOT 把固定用户或用户 Bearer token 当作 Agent callback 与内部服务的身份。

#### Scenario: Agent callback 请求

- **当** Agent 调用 `/internal/**` callback
- **那么** 请求不经过用户会话认证
- **并且** callback 继续使用独立的服务认证机制

#### Scenario: 用户 token 调用内部接口

- **当** 调用方只携带用户 Bearer token 请求 `/internal/**`
- **那么** 用户 token 不赋予内部服务权限
