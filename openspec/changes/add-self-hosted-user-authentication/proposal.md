# 变更：新增自建账号与可信用户认证

## Why

当前所有用户私有 API 都直接相信查询参数或请求体中的 `userId`。虽然资产、记账、自选和持仓链路已经按用户 ID 过滤，调用方仍可篡改 `userId` 读取或修改其他用户数据，Server 没有可信身份来源。

本变更来源于安全评审中的 P0 问题，以及用户确认采用自建用户名密码体系的决定。新注册账号不继承当前固定用户 1 的任何历史资产、记账、自选或持仓数据；开发环境仍需保留无需登录的固定用户调试方式。

本变更不依赖现有 PRD。账号、会话和身份上下文由 Server 作为长期、权威、可审计的安全事实管理。

## What Changes

- 新增用户名密码注册、登录、退出和当前账号查询 API。
- 密码仅保存 BCrypt 哈希；登录成功签发高熵随机 Bearer 会话令牌，数据库只保存令牌摘要、有效期和撤销状态。
- 新增可信身份过滤器和当前用户上下文；所有 `/api/**` 请求除注册、登录和预检请求外都必须具有有效身份。
- 用户私有 Controller 只使用身份上下文中的用户 ID。兼容期内请求中的 `userId` 暂时保留，但只能与可信身份一致，不能作为权限依据。
- 新增可切换的 `fixed` 与 `session` 认证模式。开发环境默认固定用户 1，可显式切换到真实会话模式；非开发环境禁止固定用户模式。
- 新注册账号从用户 ID 2 开始分配，避免自动获得当前固定用户 1 的历史业务数据。
- 增加账号锁定、统一登录失败响应、令牌脱敏和会话撤销等基础安全控制。

## Capabilities

### New Capabilities

- `self-hosted-user-authentication`：管理本地账号凭据、登录会话、可信用户身份和用户私有 API 的认证边界。

## Impact

- 涉及 Account/Auth Domain、Case、Repository、MyBatis、API DTO、HTTP Controller、Spring Security 过滤器和应用配置。
- 新增 `user_account`、`user_session` 表及初始化/增量迁移；不修改已有业务表中的用户 ID 字段。
- 更新用户私有 Controller 的用户 ID 来源，并补充根目录 Server/Client 认证契约。
- Client 登录注册页面和令牌持久化不在本次 Server 变更范围内；现有开发模式保持无需登录可调试。
- Agent callback 与 `/internal/**` 的服务身份认证不属于本次变更，继续按现有独立机制处理。

## Success Criteria

- 新用户可注册、登录、查询自身账号并退出，且新账号看不到固定用户 1 的历史私有数据。
- 明文密码和原始会话令牌不进入数据库、日志或错误响应；错误不泄露用户名是否存在。
- 缺失、无效、过期或已撤销令牌访问受保护 API 时统一返回 401。
- 请求携带的过渡 `userId` 与可信身份不一致时返回 403，并且不执行任何业务读写。
- 开发默认固定用户 1 的调用方式保持可用；本地可通过配置切换到真实注册登录链路。
- Domain、Case、Infrastructure、Trigger 安全测试、Maven 质量门和严格 OpenSpec 校验通过。
