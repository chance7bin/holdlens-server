# 变更：管理用户记账类别

## Why

现有独立记账只提供服务端固定枚举类别。用户无法决定记账表单中显示哪些类别、调整常用类别顺序，也不能用现有 SVG 图标创建个人类别。固定枚举同时使条目、统计和图标只能识别预置代码，无法承载按用户隔离的类别目录。

本变更来源于用户确认的类别设置流程。共享请求、响应、状态、错误和兼容语义由根目录 `contracts/holdlens-server/client/bookkeeping.md` 维护，不关联或修改资产目录与资产事实。

## What Changes

- 将系统内置类别和用户自定义类别统一建模为类别定义，以 `SYSTEM/USER` scope 区分归属。
- 新增独立的用户类别配置，保存启用状态和支出、收入各自的排序，不为每个用户复制完整系统类别。
- 新增类别设置、图标目录、自定义类别创建、启用、停用和重排接口。
- 停用类别时，在同一事务内停用配置并软删除该类别下当前用户的全部活动账目；重新启用不恢复旧账目。
- 用持久化类别解析替代固定类别枚举，使明细和统计返回系统或自定义类别的名称与图标键。
- 迁移现有 23 个固定类别并保留全部既有 `category_code`；迁移本身不删除账目。

## Capabilities

### New Capabilities

- `bookkeeping-category-management`：按用户管理系统与自定义记账类别、图标、启停和排序，并维护停用类别与账目的事务一致性。

## Impact

- 涉及 bookkeeping Domain、Case、Repository、MyBatis、API DTO、Controller、数据库初始化和迁移。
- 更新根目录共享记账契约，并扩展既有分类、条目和统计响应的图标语义。
- 现有 `bookkeeping_entry` 表和类别代码保持兼容；新增类别定义与用户配置表。
- 所有写操作使用明确动作 POST，查询继续使用无副作用 GET。

## Success Criteria

- 用户只能查看和修改自己的类别配置与自定义类别，不能越权引用、停用或排序他人类别。
- 系统类别使用模板默认值和用户覆盖合并查询，查询不会隐式写数据库。
- 自定义名称、收支类型、图标白名单、幂等键和重名规则由服务端校验。
- 停用类别和批量软删除活动账目原子提交，重新启用不恢复账目。
- 现有条目、统计和账单继续识别原类别代码，并能正确返回自定义类别名称和图标。
- 迁移、相关分层测试、Maven 质量门和严格 OpenSpec 校验通过。
