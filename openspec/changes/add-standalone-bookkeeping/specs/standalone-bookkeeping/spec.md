## ADDED Requirements

### Requirement: 独立保存收支条目

系统 SHALL 按用户持久化收入或支出条目，并 SHALL 保持记账事实与资产目录、资产记录、持仓和余额完全独立。

#### Scenario: 创建有效收支条目

- **当** 用户提交大于零的人民币金额、有效收支类型、匹配分类、发生日期和可选备注
- **那么** 系统保存一条活动收支条目并返回完整结果
- **并且** 不读取或修改任何资产模块数据

#### Scenario: 重复提交创建请求

- **当** 同一用户重复提交相同 `requestId`
- **那么** 系统返回第一次成功创建的条目
- **并且** 不新增第二条记录

#### Scenario: 非法输入

- **当** 金额不大于零、超过两位小数、分类与类型不匹配、发生日期晚于北京时间今天、日期非法或备注过长
- **那么** 系统返回业务错误且不写入部分数据

### Requirement: 查询并维护用户自己的活动条目

系统 SHALL 支持按日期范围及可选类型、分类查询活动条目，并 SHALL 允许所有者修订或软删除条目。

#### Scenario: 查询日期范围明细

- **当** 用户查询不超过 366 天的有效日期范围
- **那么** 系统按发生日期和 ID 倒序返回筛选后的活动条目
- **并且** 返回同一筛选范围的收入、支出和结余

#### Scenario: 修订活动条目

- **当** 所有者提交完整、有效的可编辑字段快照
- **那么** 系统更新条目并使后续明细、统计和账单反映新值
- **并且** 不改变任何资产事实

#### Scenario: 删除活动条目

- **当** 所有者确认删除活动条目
- **那么** 系统将条目标记为已删除且不物理删除
- **并且** 后续明细、统计和账单不再包含该条目

#### Scenario: 不可见条目

- **当** 条目不存在、属于其他用户或已经删除
- **那么** 详情、修订和删除统一返回“收支条目不存在或不可见”
- **并且** 不泄露条目归属或历史内容

### Requirement: 提供稳定收支分类

系统 SHALL 提供按收支类型划分的稳定分类代码、中文名称和顺序，并 SHALL 校验条目分类属于对应类型。

#### Scenario: 查询分类

- **当** 用户按有效收支类型查询分类
- **那么** 系统按固定顺序返回该类型的全部分类

#### Scenario: 分类类型冲突

- **当** 支出条目使用收入分类或收入条目使用支出分类
- **那么** 系统拒绝创建或修订

### Requirement: 生成周月年收支统计

系统 SHALL 根据北京时间自然周期生成指定收支类型的总额、平均值、连续趋势点和分类排行。

#### Scenario: 拒绝未来统计周期

- **当** 锚点落入尚未开始的未来自然周期
- **那么** 系统返回业务错误且不返回伪造统计

#### Scenario: 周月趋势补点

- **当** 用户查询自然周或自然月统计
- **那么** 系统按日返回完整周期的趋势点
- **并且** 没有条目的日期金额为零

#### Scenario: 年度趋势补点

- **当** 用户查询自然年统计
- **那么** 系统按月返回十二个趋势点
- **并且** 没有条目的月份金额为零

#### Scenario: 当前周期平均值

- **当** 查询包含北京时间今天的当前周期
- **那么** 平均值只使用截至今天已经历的日数或月份数

#### Scenario: 分类构成

- **当** 所选周期和收支类型存在条目
- **那么** 系统按分类金额降序返回金额与百分比
- **当** 总额为零
- **那么** 分类排行为空且不产生除零错误

### Requirement: 生成月账单和年账单

系统 SHALL 查询时聚合活动收支条目形成月账单和年账单，不单独持久化账单结果。

#### Scenario: 指定年份月账单

- **当** 用户查询非未来自然年
- **那么** 系统返回该年收入、支出、结余和倒序逐月汇总
- **并且** 当前年只包含截至当前月，历史年包含完整十二个月

#### Scenario: 全量年账单

- **当** 用户查询年账单总览
- **那么** 系统返回全部活动条目的总收入、总支出、总结余和倒序年份列表
- **当** 用户没有活动条目
- **那么** 总额为零且年份列表为空
